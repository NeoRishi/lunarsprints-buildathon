Schedule construction runs entirely through the existing deterministic scheduler and validators. It saves without any AI availability. Successful explanations are reused for the same schedule hash and cleared when the underlying plan changes. Mandatory goal, work, schedule and activation approval gates are unchanged.

Canonical confirmed facts retain selected-option wording, custom input, uncertainty and provenance, replacing duplicated questionnaires/options and answer IDs in downstream inputs. Compact session contract v2.1 removes unused outer narrative fields; stage payloads still carry recommendation provenance, goal assumptions and scoped readiness evidence. Missing-scope requests, warnings and recovery remain supported. The full prior frame remains available for comparisons.

Agent 05 used `gpt-6.1-sol` by default via a **session-only override**, and an environment variable could restore its saved model without changing the saved resource. Agent 03 kept its existing model override policy; other roles kept saved models. No remote resources were created or mutated. All ten saved IDs and fingerprints remain pinned and verified before invocation. Standard service is used, with low reasoning; no premium speed tier was enabled.

## Measured comparison

`docs/evidence/planning-benchmark.json` contains four actual Agent 05 sessions: two matched synthetic workloads, each tested with Astra/full frame and 6.1 Sol/compact frame. All four passed schema, goal/criterion coverage, hierarchy, estimate sum and dependency validation. Reviewed output contained both required handbook sections/gap review and both competing goal outcomes.

| Workload | Astra/full | 6.1 Sol/compact | Time reduction |
| --- | ---: | ---: | ---: |
| Two handbook sections + gap list | 32.851 s | 26.345 s | 19.8% |
| Portfolio + two pencil sketches | 37.465 s | 36.080 s | 3.7% |

Across these two samples: elapsed time decreased 11.2%; input tokens decreased 2.3%; output tokens decreased 13.1%; total tokens decreased 4.5%. Application input character count decreased 28.3% and response schema size 18.8%; saved agent instructions still account for much of the provider input. Token counts are provider-recorded, reconciled through the official turn metadata endpoint after the sessions completed. Characters are not token estimates.

This compares the combined profile, not isolated effects of model vs contract. Different generated task counts and prompt-cache hits affect usage. Two samples do not establish p95 latency, universal quality, dollar savings or hardest-case coverage. The larger guaranteed saving is avoiding two default-path model calls: cosmetic introduction and mandatory schedule commentary. Optional advice is separately requested and billed.

## Usage measurements and migration

Migration `20261031095139_lunarsprints_agent_metrics.sql` adds **only** `public.ls_agent_runs.metrics jsonb`, with an object constraint and empty default for historical rows. The CLI generated the source file first; its timestamp was reconciled to the actual MCP-applied migration version. No other tables, auth triggers, OAuth/SMTP settings or redirects were changed. Existing owner-only RLS and grants remain in force and are checked in database tests.

Each run records effective model, contract version, input/schema/output character counts, first provider-output latency, total duration, result classification and available input/cache/output/reasoning tokens. No prompts, responses, secrets, cookies or headers enter this metrics field. First output measures provider SSE, not client-visible streaming.

Provider usage can be missing from stream/turn results or arrive later. After the HTTP response, Next.js `after` runs one bounded 5-second read-only metadata lookup for each missing usage record, then persists telemetry. There are no retries or extra model calls. Unknown values remain null and `usageSource` identifies their origin. Background telemetry is best effort and is not a durable queue; a host shutdown or provider metadata delay can leave usage unavailable. This is neither zero usage nor evidence of zero billing.
